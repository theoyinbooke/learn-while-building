30-second learning brief

What happened
The project was split into a small teaching skill, structured lesson data, and a stable HTML renderer.
Why it matters
The agent can adapt explanations to each learner without redesigning the page or weakening accessibility on every run.
What changed
Learning goals, project evidence, review questions, and visual descriptions now enter one validated data format before they become a lesson.
What to learn
Separate variable content from fixed presentation when one part needs to adapt and the other needs to stay predictable.
Verification
The package tests validate the lesson data, render the page, and check its quiz and responsive layout. The optional network 3D enhancement is not required for the lesson.

Your learning goal

Explain how the skill separates adaptive teaching content from a stable renderer, and identify why that separation makes the result safer to update.

Before and after

Before

An agent could generate a different page structure and visual style for every lesson.

After

The agent generates validated lesson data, then one renderer applies the same readable structure and accessibility rules.

Why it works: A stable boundary makes both content adaptation and interface testing easier to reason about.

How to think about it

Separate content from presentation

Content is the meaning of the lesson. Presentation is the layout and interaction used to communicate it. Keeping them separate lets each change for a clear reason.

In this project: The agent writes the summary and questions in JSON. The renderer decides typography, spacing, keyboard behavior, and the visual fallback.

Use project evidence as the source

An explanation becomes useful when it points to the actual decision, file, test, or behavior that produced it.

In this project: This lesson cites the schema, validator, renderer, and package tests instead of describing an imaginary application.

Make enhancement optional

A richer feature should not remove the basic path. If it fails, the learner still needs the full explanation.

In this project: The 3D view loads only after a button press. A labeled static relationship remains visible before and after that choice.

Evidence used

  • SKILL.md defines when and how the agent teaches.
  • lesson-schema.md defines the content contract.
  • validate_lesson.py rejects incomplete or disallowed lesson copy.
  • render_lesson.py creates one self-contained HTML page with an offline fallback.

Try it yourself

1. The learner changes their goal from understanding tests to understanding architecture. Which part should change first?

2. The Three.js module cannot load while the learner is offline. What should happen?

3. If the renderer did not show a fixed end marker after the short brief, what confusion could that create for the learner?

Guidance: Consider the learner who wants only the quick understanding and the learner who wants the full technical response.

Model answer: The learner could not reliably tell which information belongs to the promised short learning artifact and which belongs to the normal agent response. That makes the time promise unclear and makes the format harder to scan.

Connection to the project: The fixed marker is an interface boundary. It gives both reading paths a predictable point of separation.

# Learning Diff

Use a Learning Diff after substantial work, in Deep mode, or during an explicit review. It is a compact map from the software change to the learner's new reasoning ability.

## Format

```markdown
## Learning Diff

### Software change
What changed in the actual project.

### Why it works
The causal explanation, not only a description.

### Mental model
The reusable idea in plain language.

### Project trace
- `path/to/file`: the relevant decision or behavior
- `test or command`: the evidence

### You can now
- predict a concrete outcome
- modify a nearby case

### Verification and limits
What was proved, what was not, and whether the evidence may be stale.
```

Keep every claim grounded in the active project. Use clickable file links when the host supports them. Do not invent a learner capability. Phrase `You can now` as an available practice target until the learner demonstrates it.

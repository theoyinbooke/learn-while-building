# Modes and gradual handback

## Modes

### Quiet

Use by default. Put the maximum 30-second learning brief first, include its fixed end marker, then continue the normal task response. Do not add a learning question unless the work itself needs one.

### Coach

Use when the learner asks to participate, has an active learning goal, or benefits from a small check. Include the brief, then one project-grounded prediction, explain-back, debugging, or code-reading prompt at a natural decision point. Do not quiz after every update.

### Deep

Use only when requested, configured, or clearly warranted by a substantial review. Include the brief, Learning Diff, project trace, practice, and optional lesson or visualization. Keep the software outcome visible and do not turn the response into a generic course.

## Gradual handback ladder

Use the lowest stage that creates useful practice without blocking the work.

1. The agent explains and implements while naming the important decision.
2. The learner predicts an outcome, then the agent implements and compares evidence.
3. The agent provides a partial solution and asks the learner to complete one bounded part.
4. The learner makes a small change while the agent reviews safety and correctness.
5. The learner proposes the plan and verification, then the agent reviews it.
6. The learner completes a nearby task with support available.

Advance after demonstrated understanding, not after elapsed time or confidence alone. Move down a stage when a misconception appears, the task becomes risky, or the learner asks for more support.

## Good evidence

- a correct prediction with a reason
- an explanation tied to a real file or behavior
- finding and repairing a bug with appropriate verification
- modifying a nearby case without copying the original answer
- proposing a safe plan and selecting the right test

Multiple-choice correctness is a weak signal unless followed by reasoning or transfer.
